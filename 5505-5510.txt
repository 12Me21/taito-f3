interconnect

each channel carries a stereo 16bit serial pcm audio signal, at a varying sample rate.

OTIS channels:
0 - unused
1 - output to ESP channel 0
2 - output to ESP channel 1
3 - output to ESP channel 2

ESP channels:
0 - input from OTIS channel 1
1 - input from OTIS channel 2
2 - input from OTIS channel 3
3 - output to DAC

connections determined by comparing signals using oscilloscope:

otis.6 (ser0) → nc?
otis.7 (ser1) → FCM → esp.15 (serio0)
otis.8 (ser2) → FCM → esp.14 (serio1)
otis.9 (ser3) → FCM → esp.13 (serio2)
esp.12 (serio3) → FCM → dac.3 (data)

OTIS Host Serial Control register set to $63 [01100011] (todo check all games do this)
- SONY SLAVE MODE
- SER3: output
- SER0-2: inputs

ESP SERMODE register set to $07F8 [0000011111111000] (todo check all games)
- normal

The protocol is something similar to I2S, which they just call "Sony".
See 5510 datasheet for information.  3 clock signals: BCLK, WCLK, LRCLK, are shared between all channels

the FCM is replacing a 74x174 4x D flip-flop (see schematics for otis/esp systems like https://archive.org/details/eps-16plus-schematics/page/n9/mode/1up)
where output channels connect to D, input channels connect to Q, and clk is driven by.. i'm not sure.. perhaps otis's bclk?

the FCM also replaces a 74x373 8x transparent latch,
with the D inputs connecting to some of the RA/D (ram address/data) pins of the 5510, and the Q outputs connecting to the ram, or something like that basically. GATE drives the clk input.

---

final audio signal going to the DAC:

- DATA changes at BCLK **rising** edge (½ cycle earler than I2S)
- LRCLK changes at BCLK falling edge, in the middle of the data bit before the MSB of the next sample.
- the cycle length of LRCLK is 128 BCLK cycles:
 - 16 bits **high** - left sample
 - 112 bits low - right sample (only the first 16 bits are real data)
 - (phase of LRCLK is backwards from I2S; see 5505/5510 datasheets. first sample is LRCLK high = left)

the DAC expects actual I2S input (unlike the otis/esp which sorta do their own thing)  and idk how the data offset doesn't break it, but whatever.
it expects I2S left/right meanigns, so its output would seem to be backwards from the internal channels.
I don't have confirmation of the pinout of the stereo audio output connector (labelled "S") so i can't confirm whether the final output uses the otis/esp ordering or the dac ordering.  but probably it is the former, based on hardware recordings i have heard (assuming their stereo was connected and recorded correctly) and based on mame.
